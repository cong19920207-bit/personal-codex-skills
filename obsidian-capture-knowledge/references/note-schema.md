# 笔记 Schema

## Frontmatter

每篇笔记严格使用以下八个字段：

| 字段 | 含义 |
| --- | --- |
| `title` | 基于当前主题生成的简短通用标题，不使用案例固定标题。 |
| `category` | 唯一主目录，例如 `20 Learning` 或 `30 Research`。 |
| `created` | 首次创建日期，`YYYY-MM-DD`。 |
| `updated` | 最后实质更新日期，`YYYY-MM-DD`。 |
| `status` | `draft`、`active`、`completed`、`archived` 或 `needs-review`。 |
| `tags` | 主题和跨域属性的 YAML 列表。 |
| `progress` | 推进状态；阶段总结固定为 `in-progress`，其他可为 `planning`、`active`、`blocked` 或 `done`。 |
| `related` | 关联笔记的 YAML 列表；没有已知关联时必须写合法空数组 `[]`。不得保留 `待补充`、模板变量或伪双链。 |

## 正文

按实际内容从以下章节选择，或使用模板中更贴合类型的章节名；没有内容的章节和占位符必须删除。

1. 事情概述
2. 起因与背景
3. 目标
4. 经过
5. 关键决策
6. 结果
7. 可复用知识
8. 问题与经验
9. 后续行动
10. 精选外部资料
11. 关联笔记
12. 更新记录

## 外部链接记录

只保留满足至少一项的链接：支撑关键事实、实际影响方案或决策、值得以后重读或继续研究。每条使用：

```yaml
- title: "资料标题"
  url: "实际完整 URL"
  reason: "为什么保留"
  supports: "它支持的结论；若仅供重读，明确说明尚不支持当前结论"
  accessed: "YYYY-MM-DD"
  publisher: "发布者（可选）"
```

`title`、`url`、`reason`、`supports`、`accessed` 必填，`publisher` 可选；不要用 `待补充` 代替未知事实，不虚构内容。

## 标题、路径和碰撞

- 文件名使用 `YYYY-MM-DD-简短标题.md`；标题描述内容主题，去除敏感原值和文件系统不安全字符。
- 新建前检查完整路径。若已存在，禁止覆盖，生成最短无冲突候选（`标题-2`、`标题-3`……）并报告实际路径；已有新建授权不因安全后缀失效。用户要求精确路径或先预览时，按主技能协议处理。
- 若用户实际想更新碰撞文件，转入续写契约，不能把新建确认当成更新授权。

## 续写

保留原 `created`，更新 `updated`，合并同类章节，去重标签和链接；在“更新记录”追加日期、摘要与依据。只清理本次涉及部分的模板残留，保留真实待办和未决事项；若无真实关联，使用 `related: []`，不清空既有有效关联。只修改已授权片段，不重排、删除或覆盖无关内容。

## 安全与证据标记

- 将密钥、令牌、密码、Cookie、个人标识、内部字符串和未脱敏数据改写为类别描述。
- 用 `事实：`、`推断：`、`待验证：` 标记证据状态。
- 未决冲突记录双方内容、日期和来源并标记 `待验证`；用户已明确替换的决定记录其替代关系，不重新要求确认。
- 明确当前可见信息范围；不得伪称读取不可见历史。
