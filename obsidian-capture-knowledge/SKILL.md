# Obsidian 知识沉淀

将当前可见对话提炼为可独立阅读的 Obsidian 笔记。固定 Vault 是 `/Users/umark/Desktop/MYLAB/MYLAB`。明确要求保存、新建或续写即授权范围内的常规新建或更新；用户要求先预览时只预览。目标歧义、未授权的覆盖、迁移、合并或删除，按下面的协议处理。

## 先选择一种操作

| 明确意图 | 操作 | 必读资源 |
| --- | --- | --- |
| 沉淀本次对话 | 首次沉淀 | `references/classification-rules.md`、`references/note-schema.md`、`assets/conversation-note.md` |
| 阶段总结 | 阶段总结 | 同上 |
| 更新本次记录、续写指定笔记 | 续写记录 | `references/note-schema.md`、目标笔记 |
| 整理知识库 Inbox | Inbox 整理 | `references/classification-rules.md`、`references/note-schema.md` |
| 提炼本次知识、形成主题卡片或操作手册 | 知识 / Playbook 提炼 | `references/classification-rules.md`、`references/note-schema.md`、对应 asset |
| 回顾本周或指定周期 | 周回顾 | `references/note-schema.md`、`assets/weekly-review.md` |

仅讨论方案且不涉及现有笔记时，不读取 Vault；用户要求只读审查现有笔记时可读取指定范围。没有明确写入意图或用户说不要写入时，不创建或修改文件。只能使用当前可见上下文和实际可访问文件，不得声称读取了未提供的历史聊天。

## 所有写入共用的范围与授权协议

按以下顺序执行，不得跳步：

1. 读取本次操作所需资源；仅在操作需要时读取 Vault 的非 `.obsidian` 内容。
2. 生成简短、通用、描述主题的标题；不得使用与某个测试或案例绑定的固定标题。文件名为 `YYYY-MM-DD-简短标题.md`，去除敏感值和不安全字符。
3. 写入前检查目标路径。新建笔记同日同名冲突时，保留原文件，使用最短无冲突后缀（例如 `-2`）并报告实际路径；安全的标题清理和后缀不自动使已有授权失效。若用户要求精确路径且冲突，或必须改变目标位置/操作类型，先澄清受影响部分。续写指定笔记按续写契约处理。
4. 需要预览时给出操作、分类依据、完整目标路径、拟写入内容和具体文件动作；常规已授权保存不强制全文预览。新建内容仅保留有实际内容的章节，不复制模板空章节或占位符；续写仅清理本次涉及的模板残留，不删除既有真实待办。没有已知关联时使用 `related: []`。
5. 仅在用户要求先审阅、目标不唯一或动作缺少授权时等待。已有具体决定在原范围内有效；用户明确调整标题、分类或内容即授权该调整，更新相关字段并复查路径即可。新增实质取舍或敏感动作单独澄清，不重复询问是否开始。
6. 只执行已授权动作。新建时仅按需创建目标目录，使用可用文件工具写入；不得预建完整目录树。更新时保护无关内容。

删除、替换整篇既有笔记、移动或合并须有对应具体授权。先明确源路径、目标路径（如有）、内容保留方式和影响；用户可一次批准明确列出的批次，无需逐文件反复确认。泛称“整理全部”不授权未说明的删除或破坏性覆盖；已授权的指定笔记续写不等同于整篇替换。

若 Vault 或目标不可访问，停止并报告真实路径、尝试的操作和实际权限/不存在错误；不得改写到其他目录、临时目录或替代 Vault。不得初始化、配置或修改 `.obsidian`，也不得把正式 Vault 用作测试环境。

## 六类操作契约

### 首次沉淀

依据当前可见对话使用 `conversation-note.md` 起草。按分类优先级选择一个主目录；提炼起因、经过、结论和行动，不逐字保存聊天、工具输出或无影响重复内容。按共用范围与授权协议新建。

### 阶段总结

记录已发生经过、当前结论、阻塞点、未验证假设和下一步；frontmatter 的 `progress` 必须是 `in-progress`，正文不得把未完成事项写成结果。按首次沉淀流程处理；预览要求取决于当前授权。

### 续写记录

1. 用户明确给出 Vault 内路径时优先使用该文件；先验证它位于固定 Vault 内且不在 `.obsidian`。路径不存在或不可读则报告真实错误并停止。
2. 未明确路径时，在非 `.obsidian` 内容中按文件名、标题、标签、双链和主题搜索。
3. 唯一可靠匹配：在已授权续写范围内更新并报告目标路径和变更摘要；用户要求先预览时才等待审阅。
4. 多个候选：列出完整路径与区分信息，停止并请用户选择。
5. 无可靠匹配：明确说明未找到并停止，请用户指定路径或选择新建；不得猜测或修改近似文件。
6. 按授权和 schema 合并：保留 `created`，更新 `updated`，去重标签和链接，在“更新记录”追加依据；只清理受影响部分的模板占位符，保留真实未完成事项和有效关联；不复制整篇，不重排或覆盖无关内容。

### Inbox 整理

读取请求范围内 `00 Inbox` 的非隐藏 Markdown；指定部分笔记时不遍历全部内容。整理方案列出各条目的来源、目标、分类、合并/保留方式和影响；具体批次已经授权则执行，否则集中提交必要决策。移动、合并、删除遵守共用授权协议，未授权条目保持不变；不因批次里一个条目未决而阻塞其余已授权动作。

### 知识 / Playbook 提炼

- 只有经过验证、可跨场景复用的稳定结论才使用 `knowledge-note.md` 写入 `60 Knowledge`。
- 可重复执行的步骤、SOP、检查清单或排障流程使用 `playbook-note.md` 写入 `70 Playbooks`。
- 若证据不足，标为推断或待验证，或保留在原对话记录，不包装成稳定知识。
- 新笔记在 `related` 和正文中链接来源记录；原始记录保持不变，不删除、不移动、不覆写。按已授权范围创建；只有预览请求或新增实质决策才等待。

### 周回顾

使用用户指定日期范围；“本周”等可由当前日期与时区唯一确定时直接采用并说明范围，确有歧义时才询问。只汇总范围内实际可访问的新增内容、关键决策、未完成事项和可提炼知识，使用 `weekly-review.md`，主目录为 `90 Reviews`。若同周期回顾存在，按续写契约处理；否则按新建协议处理。

## 内容与安全契约

- frontmatter 严格使用 `note-schema.md` 的八个字段；模板中的章节是候选结构，不是必填清单，删除所有空章节和占位符。
- 外链只在以下任一条件满足时保留：支撑关键事实、实际影响方案/决策、值得以后重读或继续研究。每条必须记录标题、URL、保留原因、支持的结论、访问日期；publisher 可选。删除未使用、低质量或重复链接，不虚构字段。
- 密码、令牌、API Key、Cookie、密钥、个人标识、内部字符串及其他敏感原值不得出现在预览、标题、路径或文件中；只保留理解所需的抽象描述。
- 用 `事实：`、`推断：`、`待验证：` 区分证据状态。未解决的冲突保留双方内容、日期和来源并标记 `待验证`；用户已明确替换旧决定时记录替代关系，不重新要求同一确认。
- 每篇笔记只有一个主目录；交叉属性用标签和 `[[双链]]` 表达。

## 执行前最后检查

将检查合并为一次：动作在有效授权内；真实目标路径位于固定 Vault 且不在 `.obsidian`（包括符号链接解析后）；目标碰撞已处理；frontmatter 八字段齐全；本次生成内容无模板残留；既有内容和真实待办未被误删；关联和外链符合 schema；无敏感原值；冲突与不确定性已标记。写后核对受影响文件与预期变更，不重复扫描整个 Vault。
