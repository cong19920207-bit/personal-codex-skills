# 正式契约整合验证

仅在里程碑编排方完成正式契约合并并交接验证时读取。无契约增量由编排方记录
`NOT_APPLICABLE`，不进入本模式。

输入包括全部有效里程碑临时契约、合并后正式契约、受影响实现、计划中的最终契约
闸门、相关项目规范及共享进度记录。所有契约均为只读来源，不重新开发或修改契约。

验证范围：

- 每项有效增量在正式契约中有唯一且语义一致的落点，无遗漏、重复、冲突或误废弃；
- 受影响契约对象与实际实现一致；
- 纯文档契约完成增量映射及代码一致性复核；机器可读或参与构建、生成、运行的契约
  必须有实际消费链路的验证证据，按风险补齐 schema、生成、类型、构建及受影响回归。

按主文件的证据复用规则使用仍有效的结果；合并改变了消费链路时必须验证变化后的
结果。没有真实运行证据，不声称外部链路无异常。

每项必需检查记录“通过、未通过或无法执行及原因”，写入共享记录并提交
`CONTRACT_VERIFICATION_READY`，包括失败或无法执行的真实结果；该状态只代表证据
交接，不代表验证通过。问题交回编排方，不自行修改代码或正式契约。

只有编排方可以根据证据判定 `CONTRACT_MERGED_VERIFIED` 或 `BLOCKED`。已有编排
授权时直接交回继续，不以内部交接代替任务完成或要求用户重复授权。
