# 执行进度与证据记录模板

仅在需要持久化且无适用现有记录时使用本模板；普通更新不重读。默认保存或合并到 `{phase_dir}/execution/{功能名}开发执行记录.md`。`{功能名}` 优先
复用既有名称，否则采用来源文档标题或清晰短名；仅重名、覆盖或对外命名取舍需确认。两个 Skill 共用这一份记录，不分别创建计划进度和执行进度。独立执行没有
里程碑时，相关闸门字段填写“不适用”。已有活跃进度记录位于其他路径或使用旧文件名
时继续复用，不自动重命名、复制或迁移。

```markdown
# {功能名}开发执行记录

> 更新时间：{YYYY-MM-DD HH:mm}
> 功能名：{已确认功能名}
> 执行模式：计划开发 / 文档修复 / 正式契约整合验证
> 执行工作区：{phase_dir}/execution
> 实施计划：{路径与版本；没有则写无}
> STEP 或复查来源：{路径、编号与版本}
> 当前里程碑：{编号；不适用则写无}
> 当前执行项：{STEP、修复项编号或正式契约整合验证}
> 闸门交接状态：NOT_APPLICABLE / NOT_REACHED / GATE_EVIDENCE_READY / GATE_DECIDED
> 契约整合状态：NOT_APPLICABLE / NOT_STARTED / CONTRACT_MERGED_PENDING_VERIFICATION / CONTRACT_VERIFICATION_READY / CONTRACT_MERGED_VERIFIED / BLOCKED

## 工作项状态

| 工作项 | 原范围或完成标志 | 状态 | 改动位置 | 下一动作 |
|--------|------------------|------|----------|----------|
| {编号} | {准确引用或摘要} | NOT_STARTED / IN_PROGRESS / IMPLEMENTED / VERIFIED / BLOCKED / NO_CHANGE_NEEDED | {路径或无} | {动作} |

## 验收证据

| 工作项 | 验收点 | 验证层级 | 命令或操作及原执行时间 | 结果 | 证据摘要与本次复用依据 |
|--------|--------|----------|------------|------|----------|
| {编号} | {原完成标志或行为} | 单元 / 集成 / E2E / RUNTIME / 静态检查 | {内容} | 通过 / 未通过 / 未执行 | {输出、路径或观察} |

## 阻塞与外溢

| 工作项 | 问题证据 | 原执行边界 | 预计影响 | 已尝试修复 | 所需决策 |
|--------|----------|------------|----------|------------|----------|
| {编号或无} | {证据} | {边界} | {影响} | {内容} | {决策或授权} |

## 里程碑闸门交接

- 闸门要求：{实施计划中的原要求；未到达则写不适用}
- 执行器提交证据：{证据摘要或位置}
- 执行器交接状态：NOT_APPLICABLE / NOT_REACHED / GATE_EVIDENCE_READY
- 里程碑判定：不适用 / 待 `$milestone-step-execution` 判定 / 通过 / 未通过 / 阻塞
- 判定依据：{由里程碑 Skill 填写}

## 正式契约整合闸门

- 全部临时契约：{路径列表或不适用}
- 合并后的正式契约：{路径或不适用}
- 增量完整性：{逐项映射结果、遗漏、重复、冲突或误废弃情况}
- 实现一致性：{受影响对象、实现定位与对照结果}
- 合并后回归：{schema、生成、类型、构建、测试或 RUNTIME 命令与结果}
- 执行器交接状态：NOT_APPLICABLE / NOT_REACHED / CONTRACT_VERIFICATION_READY
- 最终契约判定：不适用 / 待 `$milestone-step-execution` 判定 / CONTRACT_MERGED_VERIFIED / BLOCKED
- 判定依据：{由里程碑 Skill 填写}

## 会话恢复点

- 当前代码状态：{摘要}
- 最近完成的验证：{内容}
- 未验证内容：{内容}
- 下一步唯一动作：{内容}
- 恢复时核对：{源版本、代码、配置、依赖、数据与环境；未变证据复用，变化项重验}
```
