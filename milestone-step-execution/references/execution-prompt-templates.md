# 执行交接模板

只读取当前交接所需模板；`{路径}` 使用已知有效路径，缺失时定向查找。交接只能引用原 STEP，不得
改写需求、任务或完成标志。

模板 B、C、G 只传递本次授权范围、来源路径和结果接收字段，不重复
`$execute-approved-work` 的执行规则。它们只用于用户已明确授权的 `standalone`
执行编排；模板 G 还要求工作流已经到达正式契约整合阶段。总控 `orchestrated` 模式
不得自动调用这些执行模板。

## 模板 A：生成里程碑草案

```text
请读取已确认的 PRD、开发 STEP 和项目规范，只做执行编排。

输入：
- 功能名：{已确认功能名}
- PRD：{路径}
- STEP：{路径}
- 项目规范：{路径列表}
- 用户指定阶段或节奏：{内容；未指定则写“无”}

根据依赖、可独立验收成果、风险、冲突和用户约束，提出 M1…Mn 草案。
阶段数量不得套用固定模板。列出每个阶段的目标、STEP、顺序、可并行候选、
明确排除项、验收方式、契约适用性、需要时的临时契约位置和闸门，并解释划分依据。
新阶段没有既有执行路径时，统一使用 `{STEP所在目录}/execution/`，其中保存
`{功能名}开发里程碑文档.md`、共享的 `{功能名}开发执行记录.md` 和按需创建的契约
或证据目录。

按用户请求输出或保存规划草案，不实施代码。集中提出尚未决定的范围/关键取舍；已确认部分不再次询问。
```

## 模板 B：执行单个 STEP

```text
使用 $execute-approved-work 执行以下已确认工作。

交接类型：单个 STEP
功能名：{已确认功能名}
当前里程碑：{编号与名称}
本次授权范围：只执行 {STEP 编号}

来源：
- 执行工作区：{路径}
- 实施计划：{路径}
- STEP 原文：{路径和编号}
- 验收清单：{实施计划路径和定位}
- 进度记录：{路径}
- 项目规范：{路径列表}
- 契约增量记录：{路径或项目约定的记录方式}

返回字段：
- 工作项状态与改动文件
- 每条验收点的实际验证证据
- 契约增量
- 阻塞、风险或外溢
- 进度记录更新结果
- 到达里程碑边界时：GATE_EVIDENCE_READY 与闸门证据

执行器不得判定里程碑通过或进入下一里程碑。
```

## 模板 D：里程碑验收

```text
由 $milestone-step-execution 判定里程碑 {编号与名称}，不要开发新功能。

依据：
- 实施计划：{路径}
- STEP 原文：{路径}
- 进度与验证证据：{路径}
- 执行器交接状态：GATE_EVIDENCE_READY

对照计划逐条判定：通过 / 未通过 / 阻塞，并附证据。复用前提未变的有效证据，只补缺失/失效或计划明确要求重跑的验证，
不要新增验收要求或修改业务代码。只有全部 STEP 完成且验收条件满足时才能由
$milestone-step-execution 判定闸门通过；否则列出缺口并停留在当前里程碑。通过且下一阶段已获授权时由编排方继续，不等待重复点名。
```

## 模板 E：汇总里程碑临时契约

```text
里程碑 {编号与名称} 已通过验收。
核对本里程碑 STEP 的契约增量；无增量时在共享记录注明依据即可，有增量时按项目既有规范汇总到：{临时契约路径}。

只记录本里程碑的新增、变更、删除、兼容和迁移影响。
标注来源 STEP，不修改正式契约文档。
```

## 模板 F：整合正式契约

```text
全部里程碑已完成并通过业务总验收。全范围无契约增量时记录 NOT_APPLICABLE 及依据，跳过模板 F/G/H；有增量时由 $milestone-step-execution 整合正式契约。

读取：
- 所有里程碑临时契约：{路径列表}
- 项目正式契约：{路径}
- 项目契约规范：{路径}
- 共享进度记录：{路径}

按现有结构统一整合所有有效变更。更新语义相同的已有条目，避免重复；
检查跨阶段冲突、废弃项、兼容和迁移说明。保留临时契约作为快照，
并在进度记录 {路径} 中将状态记为 CONTRACT_MERGED_PENDING_VERIFICATION。

有增量时这一步不宣布整个功能完成。写入后按既有授权使用模板 G 交接验证。
```

## 模板 G：验证正式契约整合

```text
使用 $execute-approved-work 验证正式契约整合结果，只提交证据，不判定最终闸门。

交接类型：正式契约整合验证
来源：
- 实施计划：{路径}
- 全部里程碑临时契约：{路径列表}
- 合并后的正式契约：{路径}
- 受影响实现位置：{路径或符号列表}
- 项目规范与既有验证入口：{路径或命令}
- 共享进度记录：{路径}

验证要求：
- 逐项核对有效临时契约在正式契约中的唯一落点；
- 对照当前实现检查接口、数据、事件、配置、权限及其他受影响契约对象；
- 按契约载体和影响风险运行相关 schema、生成、类型、构建及受影响回归；
- 不修改需求、STEP、临时契约、正式契约语义或业务代码。

返回字段：
- 增量完整性证据
- 实现一致性证据
- 合并后回归命令、结果与运行证据
- 未通过项、影响和外溢判断
- 进度记录更新结果
- 交接状态：CONTRACT_VERIFICATION_READY

每个必需检查都要记录“通过、未通过或无法执行及原因”。即使存在失败或无法执行项，
也应提交 CONTRACT_VERIFICATION_READY 供里程碑 Skill 判定；不得标记整个功能完成。
```

## 模板 H：判定正式契约整合闸门

```text
由 $milestone-step-execution 判定最终契约闸门，不开发新功能。

依据：
- 实施计划及正式契约整合闸门：{路径和定位}
- 全部临时契约与合并后的正式契约：{路径}
- 执行器验证证据：{进度记录或证据路径}
- 执行器交接状态：CONTRACT_VERIFICATION_READY

本模板用于有契约增量的整合。只有增量完整性、实现一致性和受影响回归全部通过，才能标记
CONTRACT_MERGED_VERIFIED 并结算整个功能完成。任一项未通过或证据缺失时标记
BLOCKED；只允许修正不改变既定语义的机械合并错误，其他情况触发外溢门禁。
```

## STEP 契约增量格式

```markdown
### {STEP 编号} 契约增量

- 变更类型：新增 / 修改 / 删除 / 无契约变化
- 契约对象：{数据、接口、事件、配置、权限、枚举或项目定义的其他对象}
- 变更内容：{准确描述}
- 兼容或迁移影响：{无或具体说明}
- 验证证据：{测试、命令或检查结果}
```
