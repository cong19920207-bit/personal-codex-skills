# 文档归纳

## 目标

参考成熟项目的文档治理方式，整理当前项目 `docs/`，让人和 Codex 能快速找到项目现状、需求、决策、契约、开发步骤、进度、测试和技术债。保留已有文档；缺少证据时标记待补充，不猜测事实。默认以文档为输入；用户要求对照实现补齐时，按下面的证据交接规则处理。

需要判断目录和文档职责时读取 `references/docs-structure.md`；创建新文档类型或补齐结构时，只读取 `references/document-formats.md` 的相关部分及对应模板。既有文档的局部文字或字段修改沿用现有格式，不强制加载模板。

## 工作范围

- 只分析和修改用户指定项目的文档目录，通常为 `docs/`。
- 可以读取仓库指令文件中与文档边界有关的规则。
- 用户仅要求整理文档时，不自动扫描业务代码或运行环境。用户已要求对照实现补齐时，可定向读取必要代码和测试，或复用已有代码—文档审查流程的证据；内部交接不再次请求同一授权。
- 不修改业务代码、数据库、配置或运行环境。仓库事实不代表生产运行状态；需要额外权限或敏感操作时，仅暂停受影响部分。

## 工作流程

### 1. 盘点

1. 优先复用已知目标；需要定位时读取现有 `docs/INDEX.md` 或 `docs/llm-manifest.json`，不为单文件修改强制遍历入口。
2. 只读本次范围涉及的当前权威文档；默认排除 draft、history、archive、snapshot，除非任务需要历史对照。
3. 没有入口时只盘点 `docs/` 内现有文档，按用途分类，不扫描业务目录。
4. 仅在需要整理目录或判断文档职责时，对照 `references/docs-structure.md` 识别已有、缺失、重复、过期和无法归类的文档。

### 2. 区分已授权整理与待决定方案

用户已指定目标和修改动作，或已确认整理方案时，直接执行范围内的常规文档修改。只读评估不写文件。涉及尚未决定的权威来源切换、实质合并、目录迁移或内容取舍时，先给出具体方案：

- 当前文档结构和可用权威来源；
- 建议目标结构；
- 逐文件动作：保留、新建、补齐、移动、合并或归档；
- 缺失信息和需要用户提供的输入；
- 原文保留、快照与回退方式。

只对尚未授权且有实质影响的动作等待确认；已有决定继续有效，不因开始写入或切换阶段再次确认。

### 3. 在授权范围内整理

1. 执行已授权的范围；只有新增实质取舍或超出授权时补充方案。
2. 复用可恢复原文的版本历史；有替换、移动、合并且历史不能覆盖当前原文时才补快照或归档，避免每次小改重复备份。归档优先使用项目已有 history/archive，无约定时使用 `docs/archive/`。
3. 保留原文的恢复路径；未经相应明确授权不物理删除原文。文件“不再适合当前结构”只代表退出默认读取，不代表丢弃。
4. 新项目采用参考结构；旧项目优先保留原文件名和路径，通过 INDEX/manifest 映射，按需逐步收敛。
5. 只补齐项目实际需要的文档。没有有效文档依据、已授权核实的实现证据或明确用户决定时，使用 `needs-input`、`needs-review` 或 `planned`；实现证据只能证明实现现状，不能替代需求决定或生产验证。
6. 仅在文件路径、权威状态或路由信息发生变化时更新现有 INDEX/manifest；不为单段修改创建或重写无关索引。

### 4. 检查

- 受影响原文可从原路径、有效版本历史、history/archive 或必要快照恢复。
- 原有标题、段落、表格、代码块、链接和附件引用没有静默丢失。
- 同一范围只有一个当前权威来源。
- INDEX、manifest 和当前文档链接有效。
- 草案、历史、归档和快照未进入默认读取范围。
- 未确认内容仍明确标记为待输入或待审查。

合并重复检查，只核对受影响文档及必要引用；未变化且前提仍成立的验证可复用。报告遗漏、冲突和未验证内容，并按验收范围说明其影响；不把局部完成扩大为整体完成。

## 新旧项目处理

下表用于整体文档治理；局部任务仅处理指定文档及必要引用，不据此补建全套文档。

| 项目情况 | 做法 |
|---|---|
| 新项目或文档很少 | 使用推荐目录和模板，按实际功能创建最少必要文档。 |
| 已有完整 docs | 保留现有结构；导航确有缺失且在本次范围内时才补入口或缺失类型，避免无意义搬迁。 |
| 文档散乱或重复 | 先建立路由和权威状态，再经确认整理或归档。 |
| 只有 PRD | 保留 PRD，按需要补步骤、计划、进度、契约、测试和技术债。 |

## 禁止事项

- 为了“目录整齐”删除旧文档。
- 超出既有授权执行实质迁移、删除或权威来源切换。
- 把计划功能写成当前已实现。
- 把历史、草案或归档标成当前权威。
- 为不适用的文档类型批量创建空文件。
- 把文档整理授权扩张为修改业务代码、运行环境或生产数据。
