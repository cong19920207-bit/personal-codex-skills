# 文档格式参考

以下栏目提炼自参考项目。保留项目已有命名风格；只创建适用栏目，缺失事实标记 `needs-input`。

## INDEX

1. 文档索引标题和维护日期。
2. 默认读取边界：扫描入口、排除目录、权威规则。
3. “任务/功能 → 必读文档”路由表。
4. 产品需求与设计入口。
5. 工程协作入口：进度、测试、运维、版本。
6. 技术债与已知缺口入口。
7. 维护与核验规则。

## 项目概览

1. 项目目标和当前阶段。
2. 用户、主要场景和核心能力。
3. 功能/模块地图及文档入口。
4. 当前架构与关键数据流的文档化摘要。
5. 长期约束、术语和不变量。
6. 当前版本、已知限制和待确认事项。

## PRD

1. 元数据：版本、状态、涉及模块、最后更新、关联文档。
2. 功能背景：当前是什么、存在什么问题、改造目标。
3. 方案确认/决策记录：编号、问题、决策、状态。
4. 改动前与改动后、核心变化汇总。
5. 用户场景、功能规则、数据/状态/交互规则。
6. 边界、异常、冲突、安全和非功能约束。
7. 明确不做、依赖、风险、技术债和未决问题。
8. 验收标准。
9. 版本记录。

## 开发步骤

1. 元数据：PRD 来源、进度文档、拆解/修订日期。
2. 功能清单：功能点、优先级、依赖；列出本期明确不做。
3. 开发环节总览：STEP、模块、前置环节、复杂度。
4. 每个 STEP 固定包含：目标、前置条件、参考文档、需求原文/依据、开发任务、不在范围、测试要求、完成标志、下一步。
5. 自检清单和推荐实施波次/里程碑。

## 实施计划

1. 文档分工与基准文档。
2. 开发节奏和里程碑。
3. 每个里程碑：目标、STEP 组成、执行顺序、独立验证、完成后文档更新。
4. 依赖、阻塞、风险、回退和变更规则。
5. 契约草案/终稿更新时机。
6. 与 progress 的联动和里程碑闸门。

## 进度

1. 元数据：路径、创建时间、PRD/步骤/契约来源。
2. 进度总览：完成数、总数、完成率。
3. STEP/里程碑明细：编号、名称、状态、日期、备注。
4. 当前阻塞、待确认和下一步。
5. 契约、测试、技术债更新记录。

## 契约

`contract.md` 只负责按功能路由和说明非默认来源；正文按 scope 放在 `contract/current/`。

每份正文先写：文档 ID、权威状态、功能范围、必读依赖、相关技术债。

- API：模块/端点、所属端、鉴权、请求、响应、业务语义、异常、关联数据、状态。
- Data：表/实体名；字段、类型、必填、默认值、说明；约束和关系。
- Admin/UI：页面、菜单/路由、内容摘要、角色权限、交互和状态约定。
- Shared：全局响应、错误码、分页、时间、鉴权等共享约定。

## 技术债

`tech-debt.md` 保存编号、标题、状态、范围和唯一详情路由；详情按功能放入 `active/`。

每项技术债包含：ID/标题/状态、位置或文档证据、问题、影响、当前处理、待处理、触发时机、风险等级、关联 PRD/契约/STEP。只有满足该项验收条件且归档动作已获授权时进入 archive；已有具体同步/归档授权不重复确认，不能用源码已改代替必要运行验证。

## 审查

1. 审查对象和基准文档。
2. 文档理解摘要和总体结论。
3. 覆盖、遗漏、冲突、歧义和风险。
4. 按需求/STEP 的问题明细和覆盖率。
5. 依赖、明确不做、验收和技术债检查。
6. 分优先级建议、剩余问题和后续动作。

## 测试清单与报告

- 清单：范围、契约/需求依据、环境；每个场景包含操作步骤、预期结果、失败判定；最后列已知边界和不测项。
- 报告：时间、范围、来源文档、环境/前置；执行命令或人工步骤；期望/实际/证据/结果；失败与复测；结论、未覆盖项和待办。

## 版本记录

1. 版本口径、编号规则、当前主线。
2. 版本总览：版本、日期、状态、一句话。
3. 每个版本：状态、主题、范围、关联文档、概述、变更清单、运维备注、已知限制、代表记录。
